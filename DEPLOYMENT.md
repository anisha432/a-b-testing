# ExperimentIQ — Production Deployment Guide

## Architecture

```
┌─────────────┐     ┌─────────────┐     ┌──────────────┐
│   Frontend   │────▶│   Backend   │────▶│  PostgreSQL   │
│  (React/Vite │     │  (FastAPI)  │     │   Database    │
│   + nginx)   │     │  Port 8000  │     │   Port 5432   │
│  Port 80     │     └─────────────┘     └──────────────┘
└─────────────┘
```

**What gets deployed:**
- **PostgreSQL** — persistent database for experiments, datasets, analysis results, users, reports
- **FastAPI backend** — REST API with JWT auth, statistical analysis, PDF generation
- **React frontend** — SPA served via nginx, proxies `/api` to backend

## Deployment Options (Recommended → Advanced)

### Option 1: Docker on a VPS (Simplest & Most Control)

**Best for:** DigitalOcean, Hetzner, AWS EC2, Linode, Vultr

**Steps:**
```bash
# 1. SSH into your server
ssh root@your-server-ip

# 2. Clone the repository
git clone https://github.com/yourusername/ExperimentIQ.git
cd ExperimentIQ

# 3. Create production environment file
cp .env.production.example .env.production
nano .env.production
# Fill in real values (see below)

# 4. Build and start
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build

# 5. Verify
curl http://localhost:8000/api/health
# Frontend available at http://your-server-ip
```

**Estimated cost:** $5-12/month (smallest VPS)

---

### Option 2: Railway (Easiest Managed)

**Best for:** Quick deployment with zero infrastructure management

1. Push code to GitHub
2. Go to [railway.app](https://railway.app) → New Project → Deploy from GitHub repo
3. Add a PostgreSQL database (Railway provides this)
4. Set environment variables in Railway dashboard
5. Deploy

**Railway environment variables:**
```
DATABASE_URL=<auto-generated by Railway PostgreSQL plugin>
JWT_SECRET=<generate a strong secret>
CORS_ORIGINS=https://your-app.up.railway.app
APP_ENV=production
PORT=8000
```

For the frontend, Railway can build the Vite app and serve it with a static hosting add-on, or you can use the Docker Compose approach with a separate VPS.

**Estimated cost:** $5-20/month

---

### Option 3: Render (Good Managed Alternative)

**Steps:**
1. Create a Render PostgreSQL database
2. Create a Render Web Service for the backend (Docker or build command)
3. Create a Render Static Site for the frontend

**Backend settings:**
- Build: `docker build -t experimentiq-backend ./backend`
- Start: `./start.sh`
- Environment: `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGINS`

**Frontend settings:**
- Build: `cd frontend && npm ci && npm run build`
- Publish: `frontend/dist`
- Environment: `VITE_API_URL=https://your-backend.onrender.com`

**Estimated cost:** $7-25/month

---

### Option 4: Fly.io (Advanced, Global Edge)

Best for low-latency global deployment. Uses Docker natively.

```bash
fly launch
fly deploy
fly postgres create
fly secrets set JWT_SECRET=your-secret DATABASE_URL=...
```

## Environment Variables Reference

| Variable | Required | Description | Example |
|----------|----------|-------------|---------|
| `DATABASE_URL` | ✅ | PostgreSQL connection string | `postgresql://user:pass@host:5432/db?sslmode=require` |
| `JWT_SECRET` | ✅ | Secret key for JWT tokens (min 32 chars) | `python -c "import secrets; print(secrets.token_urlsafe(64))"` |
| `CORS_ORIGINS` | ✅ | Comma-separated allowed origins | `https://yourdomain.com` |
| `VITE_API_URL` | Optional | Frontend API base URL | `https://api.yourdomain.com` or empty for same-origin |
| `POSTGRES_USER` | Docker only | Database username | `experimentiq` |
| `POSTGRES_PASSWORD` | Docker only | Database password | Use a strong password |
| `POSTGRES_DB` | Docker only | Database name | `experimentiq` |
| `APP_ENV` | Optional | Environment name | `production` |
| `PORT` | Optional | Backend port | `8000` |
| `WORKERS` | Optional | Uvicorn worker count | `2` |

## Security Checklist

- [ ] `.env.production` is **never** committed to git
- [ ] `JWT_SECRET` is a strong, unique random string (64+ characters)
- [ ] `POSTGRES_PASSWORD` is strong and unique
- [ ] PostgreSQL port 5432 is **NOT** exposed to the internet
- [ ] CORS only allows your production domain(s)
- [ ] HTTPS is enabled (via nginx, Cloudflare, or platform SSL)
- [ ] Backend `/docs` endpoint is disabled or protected in production
- [ ] File uploads have size limits enforced (100 MB default)

## Production Configuration

### What Changes from Development

| Aspect | Development | Production |
|--------|-------------|------------|
| `APP_ENV` | `development` | `production` |
| `JWT_SECRET` | `dev-secret-change-in-production` | Strong random string |
| CORS | `localhost:5173` | Your production domain |
| Database | Local PostgreSQL | Cloud/remote PostgreSQL with SSL |
| API URL | `localhost:8000` | Your production domain |
| HTTPS | No | Yes |
| Workers | 1 (auto-reload) | 2+ (no reload) |
| DB Port | Exposed | **Not exposed** |

### Database SSL

When using a cloud database (Railway, Neon, Supabase, AWS RDS), append `?sslmode=require` to your `DATABASE_URL`:

```
DATABASE_URL=postgresql://user:pass@host:5432/dbname?sslmode=require
```

## Data Volumes

Production uses Docker named volumes for:
- `pgdata` — PostgreSQL data files
- `uploads` — User-uploaded CSV datasets
- `reports` — Generated PDF reports

**Backup strategy:** Periodically back up these volumes:
```bash
docker run --rm -v experimentiq_pgdata:/data -v $(pwd):/backup alpine \
    tar czf /backup/pgdata-backup-$(date +%Y%m%d).tar.gz -C /data .
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `DATABASE_URL is missing` | Set `DATABASE_URL` in `.env.production` |
| `Could not connect to database` | Check `DATABASE_URL`, ensure DB is running, check `sslmode` |
| CORS errors in browser | Add your frontend domain to `CORS_ORIGINS` |
| 404 on frontend routes | Ensure nginx `try_files` config is correct |
| JWT expired errors | Increase `ACCESS_TOKEN_EXPIRE_MINUTES` or re-login |
| Upload fails | Check `MAX_UPLOAD_SIZE_MB` and nginx `client_max_body_size` |
